# Activity-5-The-Product-Development-Launch-Roadmap

📋 Step-by-Step Instructions

Step 1: Team Formation & Roles (Teams Only)

In a real product team, multiple cross-functional roles work together (e.g., Product Manager, UX/UI Designer, Lead Engineer, Scrum Master).

    The Goal: Outline who is taking on which role and define their primary focus area. Carry these responsibilities through the rest of this activity.
    Important Note on Participation: Every team member must actively contribute to the repository. Git records who makes changes through commits. Each member must commit their own role definition and contribute to file creation or updates throughout the assignment to receive individual credit.
    The GitHub Action: Create the file docs/1-team.md using the template below.

Step 2: Defining the MVP

Define your Minimum Viable Product (MVP)—the bare minimum version of your app needed to solve the core problem for early users.

    The Goal: Take your 5 key features from Activity 4. Decide which 3 features are mandatory for launch (the MVP) and which 2 features can be deferred to a later version.
    The GitHub Action: Create the file docs/2-mvp-scope.md using the template below.

Note: you can refine the 5 features as you work on this activity.

Step 3: Tech Stack & Hosting Strategy

Determine the tools required to build your application and make it accessible to your audience.

    The Goal: Define the programming languages, frameworks, or tools you will use, along with your live hosting environment.
    The GitHub Action: Create the file docs/3-tech-stack.md using the template below.

Step 4: Planning for Friction & Technical Debt

In the real world, things break, APIs fail, or deadlines creep. You must proactively plan for constraints.

    The Goal: Look at your 3 chosen MVP features. Identify the single highest-risk technical or design bottleneck and write an actionable backup plan.
    The GitHub Action: Create the file docs/4-risk-matrix.md using the template below.

Step 5: The Go-To-Market Checklist

A product isn't successful just because it's built; it has to be successfully shipped, tested, and marketed.

    The Goal: Outline your exact marketing channel, value proposition, pre-launch QA checks, and launch day protocols.
    The GitHub Action: Create the file docs/5-launch-plan.md using the template below.
